# Memo

Persist and recall repo-scoped notes across sessions.

## Storage layout

Save memory files under the memo directory:

`~/.copilot/memo/[DATE]-[ID]-[repo-owner]-[repo-name]-[name].md`

`[DATE]` uses `YYYY-MM-DD`. The current repository determines `[repo-owner]` and `[repo-name]`.

Using `~/.copilot/memo` keeps memos in a stable location that exists both locally and in Codespaces.

## File format

Each memory file must be markdown with YAML frontmatter that includes:

- `memo_id`: unix timestamp (`date +%s`)
- `summary`: searchable context summary (1-3 sentences, not just a title)
- `status`: `wip` or `done`
- `created_at`: ISO8601 timestamp
- `updated_at`: ISO8601 timestamp

The memo content belongs in the markdown body, not in frontmatter.

## Workflow

The workflow scripts are in this skill's `script/` directory. Resolve paths relative to this `SKILL.md` and execute the scripts directly from the user's current working directory so they scope every operation to the current Git repository. If a script exits nonzero, report its error and stop that workflow.

### 1. If user asks to **save memory**

Use this mode when the user says things like:

- “remember this”
- “save this for later”
- “memoize this decision”

Choose a short, descriptive kebab-case name from the user's input or context, then create the memo:

`script/save-memo.sh <name>`

The script prints the new file path. Replace the generated `summary` placeholder with a searchable 1-3 sentence context summary and replace the placeholder markdown body with the memo details. Preserve all other frontmatter generated by the script.

For updates, locate an existing memo with `script/recall-memo.sh <query>` and edit it in place. Preserve `memo_id` and `created_at`, and set `updated_at` to the current ISO8601 timestamp.

### 2. If user asks to **recall memory**

Use this mode when the user says things like:

- “remember what we decided about X”
- “what do you remember about Y”
- “recall notes for Z”

Run:

`script/recall-memo.sh <query>`

Pass the complete search phrase as the query. The script searches only memos for the current repository and returns the top match with its match reason. Read the `TOP_MATCH` file and answer from its contents. Default to the top match, then ask if more results are needed.

### 3. If user asks to **mark memory done**

Use this mode when the user says things like:

- “mark this as done”
- “this memo is done”
- “close out the note about X”

Run:

`script/mark-memo-done.sh <query>`

The script reuses the recall matching rules, changes the top match's `status` to `done`, refreshes `updated_at`, and preserves `memo_id` and `created_at`.

## Guidelines

- Keep memories repository-scoped; do not mix notes across repos.
- Write `summary` as a compact paragraph with enough detail to disambiguate related notes.
- Do not hard-wrap prose around column 70; keep each paragraph on a single line.
- Preserve markdown readability so files are human-editable.
